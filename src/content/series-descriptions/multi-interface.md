A human and an agent have the same problem. Both work with limited cognitive
resources, and both pay dearly for information that arrives unstructured — the
work of stitching it back together is the expensive part, not the reading.

So we stop building a page for the human and bolting an API on for the agent.
We build one thing with two outputs, designed together from the first sketch:
the same source answers HTML to a browser and markdown to an agent, the same
address resolves for a person, a script and a machine on the other side of the
network, and progressive disclosure protects a context window exactly the way
it protects an afternoon.

This series is the argument. Agent Experience and Developer Experience are not
new disciplines — they are User Experience applied to readers who happen to
have a token budget. The payoff is automation you can actually trust with your
software development lifecycle, and a place left in it for the person who has
to understand, debug and correct what the machine did.
